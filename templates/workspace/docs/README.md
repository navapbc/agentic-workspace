# Docs lanes

`docs/` is where written output lives. **The lanes below are a starting suggestion, not a rule.** Pick the ones that fit how your team works, rename them to your own vocabulary, drop the ones you do not need, and add your own. The only thing that matters is that a lane means the same thing to every teammate and their agents, so output lands somewhere predictable.

A common starting set:

| Lane | What tends to go here |
|---|---|
| `ideation/` | Early idea generation and option exploration. |
| `plans/` | Scoped plans and implementation approaches. |
| `solutions/` | Documented, reusable learnings from solved problems. |
| `references/` | Read-only source bundles: one folder per source, each with a short README and the files. |
| `pulse-reports/` | Periodic health/status snapshots. |
| `dogfood-reports/` | Notes from using your own tools/workspace. |

Create a lane folder only when you first write into it. If your team already has a docs convention (from another tool, plugin, or house style), use that instead — this kit does not require any particular lane layout.

Whatever you choose, write it down (in the workspace `README.md` under "Team decisions") so it stays shared. Directory and lane names are lowercase kebab-case; see the kit's `docs/directory-and-naming-standard.md`.
